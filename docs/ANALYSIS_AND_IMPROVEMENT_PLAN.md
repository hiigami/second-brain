# Work Second Brain requirements and improvement roadmap

Updated 2026-10-04 for the Patch N checkpoint and authorized review fixes. The roadmap below is the active development plan. This is a development plan, not a Stage 2 candidate, business approval, or authorization for a real shared index.

## Intended outcome

Help a person retrieve what is known, why it is believed, when it applied, what remains uncertain, and which project owns it, with manageable human review effort. Support varied source formats and mixed-project documents while preserving exact evidence, uncertainty, source boundaries, and human approval.

The [detailed requirements and delivery plan](REQUIREMENTS_V2_DELIVERY_PLAN.md) contains requirement traceability, source inclusion/exclusion rules, format limits, proposed file scope, dependency order, acceptance scenarios, and unresolved decisions. The eight requested source categories and all requested file formats remain in scope; partial milestones do not constitute full requirement completion.

## Decisions that must remain explicit

- **Configuration:** the five-value `project.json` v0.1 enum remains frozen. Optional `config/source-scope.json` v1.0 registers data, analysis, and policy roots; its validated snapshot and byte hash bind each new run. Source ids and resolved roots cannot overlap. Existing runs require no sidecar. Because v0.1 still requires one legacy source, a project containing only new categories remains unsupported without a later configuration decision. A file has one primary source category; Patch D adds structural spans while semantic passage classification remains later work. See [ADR 001](architecture/adr/001-additive-source-scope.md).
- **Visual evidence:** image capture, text recognition, and diagram interpretation are distinct capabilities. Adapter 0.5.0 uses the existing defused XML parser and Python standard library to preserve source-stated SVG labels/vector attributes and PNG dimensions/annotations; embedded Office/PDF visuals receive locators and unavailable issues. Adapter 0.6.0 validates PNG compressed rows without reconstructing pixel values. SVG render effects/legibility/relations and PNG visual meaning are unverified. No new model/provider, API, or OCR dependency is authorized by this plan. [Manual visual comparison](VISUAL_FIDELITY_REVIEW.md) is an interim workflow, not proof of automatic extraction support.
- **Cross-project updates:** automate proposals and routing; target approval remains human. Patch N implements shared approved-release lookup through a rebuildable index with separate whole-release authorization and operator-selected external storage. It preserves original project authority and provenance. Real access, information handling, and usefulness still need assessment. See [ADR 005](architecture/adr/005-derived-approved-release-index.md).
- **Compatibility:** Patch A fixes historical scope verification with a fixed legacy lookup and frozen policy inputs for new runs. Extractor adapter version now enters document scope comparison. Patch D binds document evidence identity to derived text, parser versions, locators, issues, and options; historical readers retain their original formula. See [ADR 002](architecture/adr/002-quotable-representation-and-segments.md).
- **HTML/EML boundary:** Adapter 0.3.0 adds these formats only to opt-in `--documents` capture. Its frozen version and extension list make changed document policies incomparable without changing engine 0.4.0 or `project.json` v0.1. HTML remains raw text without the flag. Structural labels describe source syntax, not business meaning. Scripts, external resources, visuals, and attachment bodies are unavailable and remain review issues; attachment metadata alone cannot support claims about attached content.
- **Table and CSV boundary:** Adapter 0.4.0 carries source-stated row context without inferring model relations or authority. CSV remains raw by default; structured CSV and first-row labels need explicit operator choices frozen in `manifest.documents`. Changed representation choices produce incomparable deltas. Visual diagrams and source-fidelity assessment remain required for R2/R3.
- **Event chronology boundary:** Records 0.4 attach multiple evidence-linked events to a record without borrowing the source file's date. Event and effective dates, precision, offsets, unknowns, conflicts, and relative anchors remain explicit; re-anchoring drops events that lose cited support. Patch I renders reviewed events separately from packet document-date navigation. Both use deterministic display order without asserting precedence among overlaps, supersession, authority, or an as-of active state. Structural checks cannot establish the semantic meaning of a date or claim. See [ADR 003](architecture/adr/003-evidence-linked-event-dates.md).

## General engineering lessons

This section records workflow principles without private source excerpts, business requirements, participant details, or real-project run statistics.

- Coverage must distinguish full review, deliberate triage, and deferred work. A keyword scan cannot establish that a file was read in full.
- Exact citations need enough context to preserve conditions, proposals, pending validation, and uncertainty. Structural quote matching cannot establish semantic support.
- Code is an implementation observation, not business authority. Decisions require appropriate non-repository evidence and human review of source status.
- Reconciliation must retain conflicts and unknown ownership. Neither source category nor recency establishes precedence.
- Helper scripts and intermediate outputs belong in the selected run's `work/` folder so the human review binds a reproducible audit trail.
- Capture time, document time, event time, and review time have different meanings. A late capture does not turn older content into a newer decision.
- Shared components and mentions of another project require explicit routing assessment, disclosure authorization, and separate target review.
- Real workspace configuration, evidence, and derived knowledge stay outside the engine's Git history. Synthetic fixtures remain available for regression checks.

Engine test results assess the tools; semantic quality and operational benefit require an authorized, bounded pilot.
