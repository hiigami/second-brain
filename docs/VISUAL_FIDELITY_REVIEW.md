# Visual evidence fidelity: interim review procedure

Patch G's adapter 0.5.0 preserves original SVG/PNG bytes and citable *source structure*. Adapter 0.6.0 also validates PNG compressed scanlines without reconstructing pixel values. Neither version certifies that derived labels are visible or legible, infers diagram edges/cardinality, or interprets embedded Office/PDF images. Generated canvas/geometry/asset locators and PNG text annotations are metadata, not descriptions of what a person sees. The extraction issues in `segments.snapshot.json` remain unavailable until a separate reviewed process supplies evidence; passing `kb_check.py` only verifies integrity and exact derived quotes.

For a visual that matters to a claim, a human reviewer should open the frozen original from the run and compare it with the derived evidence and extraction issues, recording the result in an authorized review artifact. Check each material label against the image; its visibility, legibility, position, and region; arrow direction and any stated cardinality; legends and captions that disagree with the visual; cropped or missing areas; and external/embedded resources that were not available. Inspect the source context and provenance before treating an SVG `<title>`, `<desc>`, text node, or PNG `tEXt` annotation as a business assertion. Preserve contradictions as unresolved rather than selecting the convenient caption.

If the original cannot be rendered or fully inspected, leave the corresponding extraction issue open and defer dependent claims. A human-written transcription or reviewed export may be captured as a **new, separately scoped source in a fresh run** after the operator authorizes that non-approval step; never overwrite a frozen original, derived snapshot, manifest, or historical fixture. The reviewer still needs to compare that transcription with the original, and publication still requires the normal human approval. This procedure does not make SVG/PNG semantic extraction or R3 acceptance complete.

The next D3 decision should use the [synthetic approved-assistant probe](VISUAL_CAPABILITY_PROBE.md) to identify an approved local interpretation/rendering boundary and representative reference cases before any further parser dependency or visual-support claim. The reference set needs known labels, graph direction/cardinality, pixel regions, deliberately illegible marks, contradictory captions, and incomplete exports, with human-scored fidelity against the original.

Use the [hash-pinned synthetic case catalog](VISUAL_REFERENCE_CASES.md) and [development review template](../templates/VISUAL_CAPABILITY_REVIEW.md) for that assessment. The new dense HTML fixture supplies ER/state diagram constructions alongside source definitions, SQL, changes, and qualified values; it closes the missing synthetic diagram case, while its two visual interpretation issues remain open. The catalog's construction oracles are not human-scored references and must not be shown to the assistant during a blind capability probe.
