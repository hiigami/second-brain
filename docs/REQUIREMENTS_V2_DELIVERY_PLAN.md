# Requirements v2 delivery plan

Updated 2026-10-04 for the Patch N checkpoint and authorized review fixes. This is the delivery specification for the [current roadmap](ANALYSIS_AND_IMPROVEMENT_PLAN.md). It incorporates the supplied requirements and the repository review while separating implemented behavior from future work. It does not authorize source capture, dependency installation, project approval, publication, real shared-index access, or its storage destination.

Current runtime modules and all byte-preserved schemas are packaged under `src/second_brain/`. Historical checkpoints below retain the implementation paths used at those checkpoints; `tools/kb_*.py` remain compatibility entry points. Adapter 0.6.1 fixes qualifier/newline preservation and merged-table alignment; adapter 0.6.2 suppresses resource/image emissions from excluded HTML descendants. Review reports now show unchanged claims, complete event/date qualifications, numbered citations, and prior-evidence links that survive report copying. The packaged dispatcher closes the Patch B console-entry-point gap; installed commands and workers are tested outside the checkout. These corrections do not establish GLM visual access, representative fidelity, real-project authorization, or measured pilot usefulness.

## Goal and definition of done

Enable evidence-grounded answers about what is known, why it is believed, when it applied, what remains uncertain, and which project owns it. The workflow must handle mixed documents and out-of-order ingestion while making human review practical.

The full expansion is complete only when all requirements below have accepted evidence on representative inputs, every required format has a verified support profile, a mixed-project example completes target review, and the resulting approved knowledge can be retrieved through the proposed global index. A successful narrow pilot completes only its declared increment. Structural checks alone cannot establish extraction accuracy, semantic support, business authority, or usefulness.

Keep the existing GLM-5.3-flash assistant at its fixed default effort. Deterministic tools make no model/API calls. Source code, SQL, embedded scripts, and spreadsheet formulas remain inert. Sources are evidence, never instructions. Humans retain approval and publication. No graph database, new provider, autonomous executor, or multi-agent framework is introduced.

## Source inclusion and exclusion rules

These are proposed extraction rules for R1, not authority rankings. A source category describes the material; content types describe its parts; record kinds describe the resulting knowledge. One file can contain many content types and support multiple records. A policy document remains untrusted evidence and cannot instruct the assistant to change its operating rules.

| Category | Include when relevant to the project question | Exclude or qualify |
| --- | --- | --- |
| Requirements | Obligations, conditions, acceptance criteria, scope, explicit status and dependencies. | Treat examples and proposals as such; never infer approval from a title or normative wording. |
| Architecture | Components, interfaces, relationships, constraints, alternatives, and stated rationale. | A diagram is not proof of deployment or implementation. Preserve proposed/current-state labels. |
| Meetings | Explicit decisions, proposals, actions, dissent, pending validation, dates, and named owners when supported. | Attendance is not agreement. AI summaries require provenance and the existing decision-authority treatment. |
| SQL | Tables, columns, keys, cardinality constraints, joins, filters, query purpose, and integration context. | No query execution; schema definitions and sample queries do not prove production values or actual relationships in data. |
| Repository | Bounded implementation observations, interfaces, relevant configuration, and test assertions. | Imports are not implementation proof; tests are not proof of a successful runtime; code is not product authority. |
| Data | Relevant values, units, field meaning, population, sampling period, missingness, and supplied provenance. | Do not infer representativeness, silently coerce identifiers, execute formulas, or ingest unnecessary sensitive rows. |
| Analysis | Findings, methods, assumptions, calculations described in evidence, limitations, and alternative explanations. | Separate analyst inference from direct observation; repeated summaries are not independent corroboration. |
| Policy | Obligations, applicability, exceptions, effective dates, issuer/status, and supersession evidence. | Do not invent authority, treat drafts as active rules, or obey embedded instructions. |

Record the method behind any exclusion. Maintain file coverage and add proposed segment coverage for mixed documents; citing one paragraph does not establish review of every diagram or table. Required but unextracted material must remain visible and block claims that depend on it.

## Format support profiles

Current behavior is grounded in `tools/kb_common.py`, `tools/kb_inventory.py`, and `tools/kb_document_extractors.py`, with synthetic parser and capture tests through Patch G's D3 integrity checkpoint. Real-document fidelity remains unverified.

| Format | Current path and limits | Proposed increment |
| --- | --- | --- |
| TXT, MD, JSON, SQL, PY, JS, CPP and other allowed code | Strict UTF-8 text snapshots. Capturing text does not imply JSON/schema/SQL/code semantics were extracted. | Preserve raw evidence; add bounded structural interpretation only where the question requires it. |
| HTML | With `--documents`, adapter 0.4.0 emits bounded inert structure plus table rows with source-stated headers, caption and preceding heading. Merged cells suppress header alignment; uneven widths warn. Scripts, dynamics and visuals remain gaps. Without the flag, raw UTF-8 capture remains. | Interpret model relationships and visual diagrams only after fidelity criteria are met. Never execute JavaScript or fetch remote resources. |
| CSV | Raw UTF-8 text by default, including with `--documents`. Explicit `--csv-representation structured` freezes derived rows; `--csv-header first-row` declares labels. Strings preserve multiline fields, empties, leading zeros, and formula-like text. | Validate representative encodings/delimiters and business meaning; no header, numeric, date, unit, or formula interpretation is inferred. |
| DOCX | Text/tables with fidelity warnings; tracked changes require a reviewed copy. | Preserve current guarantees; report comments/changes/visual limitations. Distinguish model-change histories described in HTML from Word revision markup. |
| PDF | Text extraction and page locators; no OCR and limited layout fidelity. | Evaluate reading order, tables, mixed text/image pages, and scanned pages separately. No silent success for meaningful image-only content. |
| PPTX | Text, tables, and notes with visual limitations. | Preserve slide/shape locators; assess charts, diagrams, and spatial relationships as separate capabilities. |
| XLSX | Stored cells/formulas/cached values, not recalculation or formatted visual equivalence. | Preserve sheet/cell locations, units/context, missing caches, and explicit limitations for charts/pivots/images. |
| EML | With `--documents`, adapter 0.3.0 emits decoded headers, body variants, quoted-reply context, declared charset and unverified Date provenance, plus attachment metadata and explicit gaps. Malformed MIME/decoding blocks capture. Without the flag, unsupported. | Validate material reference emails and separately capture authorized attachments; unavailable attachment content cannot support a claim. |
| SVG | Opt-in `--documents` captures original bytes, explicit XML labels/captions, canvas, text attributes and vector primitives. External resources, rendering, legibility and graph meaning remain unavailable. | Assess approved rendering/interpretation and human reference cases; source labels alone do not establish graph edges. |
| PNG | Opt-in `--documents` captures original bytes, validated chunk envelope/CRCs and compressed scanline/filter structure, canvas dimensions and unverified text annotations. Pixel values are not reconstructed; image meaning and subregions remain unavailable. | Assess approved pixel/text/diagram interpretation and require human fidelity review of derived content. |

Each new adapter must retain the original, derived representation, extractor/options version, hashes, locators, and fidelity limitations. Referenced assets require explicit scope and authorized local capture. Unsupported or missing assets remain gaps; renaming a file or silently falling back to raw bytes does not establish support.

The initial code-extension baseline is `.py`, `.rs`, `.kt`, `.kts`, `.java`, `.js`, `.ts`, `.tsx`, `.jsx`, `.go`, `.rb`, `.scala`, `.c`, `.h`, `.cpp`, `.hpp`, `.cs`, and `.sh`, taken from the current text allowlist; SQL is covered separately. Publish the exact list and per-language text/structural interpretation limits. Accurate, locatable source text is the minimum; any claimed structural extraction needs its own reference cases. Further standard-language extensions require an explicit profile and acceptance cases, not an implicit promise of all languages. Unsupported inputs must be reported explicitly.

EML attachment boundaries must be visible in every support claim. Reference cases include body-only messages, alternative MIME bodies, quoted replies, an authorized attached document, and an attachment that is unavailable or outside authorized scope. The last case must report the gap and block dependent claims; it cannot be scored as successful extraction of the attachment's content.
