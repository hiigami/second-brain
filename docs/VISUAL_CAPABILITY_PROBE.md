# D3 visual-access probe for the approved work assistant

This probe uses synthetic repository fixtures only. It tests whether the *existing approved GLM-5.3-flash work assistant*, at its fixed default effort and without a new provider/API, can inspect original visual files. A correct answer to derived text alone is insufficient. Running this probe is a separate operator activity; this checkout does not contain its result or a human-reviewed reference set.

The [reference-case catalog](VISUAL_REFERENCE_CASES.md) pins the original hashes and adds a dense HTML case with both ER and state diagrams. Keep its construction oracle out of the assistant's input. Copy the [development review template](../templates/VISUAL_CAPABILITY_REVIEW.md) into an approved development location and fill it from actual observations; its initial status is unmeasured. No verified local GLM viewing mechanism or probe result is available yet.

Use `tests/fixtures/patch_g_visual_probe.png` as the pixel-access case. Its construction oracle is a 64×32 image: red left half, blue right half, and a small yellow square spanning x=28–35 and y=12–19. The embedded PNG `tEXt` annotation falsely says that the whole image is green. Ask the assistant to inspect the **original PNG through its approved local visual mechanism**, identify the visible colors and approximate regions, and explain whether the annotation agrees. Do not provide the construction oracle or ask it to decode the fixture source code first. Record the exact local tool/path used; reading `extraction.json`, packet text, or PNG metadata cannot establish pixel access. A truthful statement that it cannot view pixels is a valid probe result, but does not establish visual support.

Use `tests/fixtures/patch_g_diagram.svg` separately for rendered-vector access. Ask which labels are actually legible, whether the arrowhead direction and cardinality are visually established, whether the `<desc>` agrees with the diagram, and whether the external image appears. The source has an intentionally low-opacity `1:N` label and an unavailable external image reference, so uncertain visibility should remain uncertain. Reading SVG XML proves source-structure access only; it cannot establish rendered legibility.

Keep the assistant's verbatim response, observed access method, date, environment, and a human comparison with the originals in an approved development review record. Score pixel and SVG access separately. Any invented color, fabricated edge/cardinality, assertion that the false PNG annotation is visible truth, or claim about an unavailable external asset fails the relevant capability. A successful synthetic probe is still only a prerequisite for representative fidelity testing; it does not complete Patch G, R2, or R3. Do not use a real project source or edit a frozen run to perform this probe.
